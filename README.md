# Оценка релевантности музыкального поиска с GigaChat-Pro

Тестовое задание на позицию Prompt Engineer: разработать промпт, который оценивает соответствие найденного трека запросу пользователя по четырём классам — `vital`, `rel_plus`, `rel_minus`, `notrel`.

## Подход

Изучил правила экспертной разметки и набор из 105 примеров. Сравнил четыре варианта промпта на 32 примерах, по восемь каждого класса. Лучший вариант — компактное дерево решений с кратким обоснованием оценки — выбрал по macro-F1 и применил ко всему набору через API **GigaChat-Pro**.

Модель получает запрос, название трека и исполнителя. Эталонные оценки используются только для расчёта метрик; ответы модели сохранены без ручной корректировки.

## Результаты

| Метрика | Все 105 примеров |
| --- | ---: |
| Accuracy | 64,8% (68 из 105) |
| Macro-F1 | 0,624 |

На 32 примерах разработки macro-F1 вырос с **0,394** у базового промпта до **0,645** у итогового. Основные трудности — слабая релевантность, запросы по текстам песен и неоднозначные музыкальные факты.

Набор использовался при разработке, поэтому результаты не являются независимой оценкой на новых данных. У 22 ответов повреждён формат JSON; метка извлечена из единственного допустимого названия класса, исходный ответ сохранён.

## Файлы и запуск

- `gigachat_pe_test.ipynb` — промпты, код, метрики и разбор ошибок.
- `predictions.tsv` — все запросы, исходные ответы модели и прогнозы.
- `valid_set.tsv` — валидационный набор с эталонными оценками.

Откройте ноутбук в Jupyter или VS Code с Python 3 и выполните ячейки. По умолчанию используются сохранённые ответы: ключ и API-вызовы не нужны. Для повторной генерации установите `RUN_API=True` и передайте ключ через `GIGACHAT_CREDENTIALS` или скрытый ввод.
